# 포트폴리오 후보 메모

2026-11-12 기준. 나중에 시연 영상이나 측정 결과를 붙일 수 있도록, 당시 고민한 대안과 선택 이유를 적어 둔다. 확인한 동작과 아직 비교할 항목은 아래에 따로 적는다.

## 초기 형태 설계

### 표면 샘플링에서 기본 도형의 부피 샘플링으로

- 메시 표면에 점을 뽑는 방법을 검토했다. 원하는 실루엣은 거인과 검의 내부까지 구체로 채워진 형태였다. 그래서 몸통·팔과 칼날·가드·손잡이 모두 기본 도형을 조합하고, 각 도형 내부에서 목표를 생성하기로 했다.
- 거부 샘플링, Jittered Grid, Weighted Sample Elimination, 반복 보정과 비교했다. 불규칙한 분포와 최소 간격을 동시에 다룰 수 있는 3D Poisson Disk Sampling을 먼저 구현하기로 했다. 후보 간 속도 우열은 측정 전이다. [초기 알고리즘 비교](../군체보스_목표위치생성_알고리즘_선정과정.md#5-비교한-알고리즘)

### 구체 크기를 고정한 채 생존 수에 맞춰 도형 축소

- 기존 좌표를 중심으로 당기면 구체 크기가 그대로인 상태에서 중심 간격이 좁아져 겹칠 수 있다. 생존 수에 맞게 배치 영역을 줄이고 목표 좌표를 다시 생성하는 쪽을 택했다. 손실은 전체 형태의 크기에 반영한다.
- 밀도와 간격을 따로 조절하는 대신 최소 중심 간격 `d`와 배치 계수 `k`로 필요 부피 `N × d³ / k`를 계산한다. 처음부터 적절한 크기를 얻도록 `k`를 조정하고, 목표 개수가 부족할 때만 제한된 횟수와 비율로 영역을 확장한다. [크기와 배치 밀도](../SwarmBossDesign.md#2-크기와-배치-밀도)

### 목표 개수에서 멈추는 대신 영역을 채운 뒤 필요한 수를 선택

- 목표 수에 도달하자마자 후보 생성을 끝내면 시작점 주변만 채워지고 도형의 다른 쪽이 비어 보일 수 있다. 먼저 영역에 후보를 퍼뜨린 뒤 필요한 개수만 무작위로 선택하기로 했다. 선택된 점들 사이의 최소 간격은 유지되며, 화면에서 얼마나 고르게 보이는지는 비교할 항목이다. [샘플링 구현 범위](Stage1README.md#구현-범위)
- 좌우 대칭 부위는 각각 무작위로 생성하면 두께와 외곽이 달라 보일 수 있다. 한쪽 목표를 반전해 분포와 내부 간격을 공유하는 방향을 택했다. 개체별 불규칙 운동으로 반복감을 줄이는 안과, 다른 부위와 만나는 경계의 간격 검증은 후속 설계다.

### 목표에서 최소 간격을 지키고 이동 중 교차는 허용

- 강체끼리 밀어내며 겹침을 해소하는 방법도 검토했다. 수백~수천 개의 밀집 개체에 물리 시뮬레이션을 적용할 때의 비용과 구현 범위를 고려해, 목표 생성 시 최소 간격을 검사하고 이동 중 교차는 허용하기로 했다. 강체 방식의 비용을 실측해 내린 결론은 아니다.
- 피격은 엔진 충돌 조회를 사용하기로 했다. 현재 클릭 실험은 `SwarmSphere` Object Type을 조회해 맞은 인스턴스를 찾는다. 실제 투사체의 이동과 관통 여부는 후속 작업이다. [피격 설계](../SwarmBossDesign.md#8-엔진-피격-처리)

### 도형별 상대 좌표와 연결부 재분배

- 도형을 움직이거나 돌릴 때 내부 배치를 유지하려고 구체의 위치를 도형 기준 상대 좌표로 저장하기로 했다. 다른 도형으로 소속이 바뀔 때는 현재 월드 위치를 기준으로 좌표를 변환해 이동이 이어지게 하는 설계다.
- 어느 도형이 몇 개를 보낼지 정하는 일과 실제로 보낼 구체를 고르는 일을 나눴다. 인접 도형의 연결부 근처에서 출발 개체와 도착 목표를 고르고, 후보가 부족할 때는 더 먼 셀로 범위를 넓히는 방향이다. 도형 기준 균일 격자라면 도형 전체의 이동·회전만으로는 셀을 갱신할 필요가 없다.
- 거인과 검 내부에 같은 연결 규칙을 쓸 수 있도록 관절을 도형과 도형이 연결되는 지점으로 정의했다. 연결 도형 추가와 SDF 결합은 실제 관절 틈을 확인한 뒤 검토할 후보로 남겨 두었다. 전체 형태 전환에 일반 재분배의 인접 이동 규칙을 어떻게 적용할지는 구현하면서 확인할 항목이다. [격자와 후보 검색](../SwarmBossDesign.md#61-fswarmspatialgrid)

### 형태와 부위의 개수 배분 규칙

- 거인과 검 N자루를 동시에 유지하는 대신 한 가지 형태로 완전히 변환하는 데모로 범위를 잡았다. 생존 구체를 새 형태에 재배치하고, 검은 N자루를 기준으로 각 검의 크기를 줄인다.
- 배정 비율을 정수로 내렸을 때 거인의 나머지는 몸통에 배정해 좌우 균형과 전체 개체 수를 유지한다. 배정량이 1 미만인 도형은 구체 배치를 생략하는 방향이다. 극소수 개체에서 실제 표시되는 검 개수와, 검 하나도 구성할 수 없을 때의 연출은 검증 전이다. [개체 수 배분](../SwarmBossDesign.md#3-개체-수-배분)

## 피격, 이동, 재구성에서 정한 것

### 개체별 Actor와 ISM 비교, 개체 ID와 화면 인덱스 분리

- 개체별 Actor는 개별 상태와 동작을 연결하기 편하지만, 데모는 많은 구체를 중앙에서 계산하고 같은 구체 메시를 반복해 그린다. 한 Actor가 데이터를 소유하고 ISM으로 표시하는 방향을 택했다. 개체별 Actor 대비 성능 우위는 측정 전이다.
- 클릭 결과는 화면의 인스턴스 번호를 주고, 소속과 목표는 개체 ID로 관리해야 한다. 개체에 `InstanceIndex`를 두고, 역방향 조회는 `InstanceToParticle`에 정수 ID로 저장했다. ISM의 인스턴스별 `float` 커스텀 데이터에 ID를 넣는 대안도 가능하지만, 현재 ID는 게임 로직에서만 쓰므로 정수 배열을 선택했다.

### 기본 삭제와 교환 삭제 비교

- 기본 삭제는 생존 인스턴스의 상대 순서를 보존하지만 삭제 지점 뒤의 번호를 모두 갱신한다. 군체 동작은 렌더링 배열 순서에 의존하지 않으므로 교환 삭제를 선택했다.
- ISM 제거가 성공하면 중앙 개체를 비활성화하고, `InstanceToParticle`도 같은 방식으로 삭제한다. 중간 항목을 지웠다면 마지막에서 옮겨온 개체 하나의 인스턴스 번호만 고친다. 개체 ID와 실제 위치는 유지된다.

### 생존 개수는 중앙에서 관리하고 비활성 슬롯을 유지

- `Particles.Num()`은 비활성 슬롯도 포함한다. 초기에는 ISM이나 `InstanceToParticle.Num()`으로 생존 수를 얻는 방안도 봤다. 여러 도형과 ISM이 생겨도 군체 전체의 생존 수를 같은 기준으로 읽기 위해 중앙의 `ActiveParticleCount`를 선택했다. 생성·제거·초기화 시점에 갱신하고, 재구성은 설정 복사본에만 생존 수를 넣는다.
- 이번 데모는 살아 있는 구체의 재배치에 초점을 맞춘다. 제거된 슬롯은 남겨 두고 생존 ID를 유지하며, 전투 중 개체 추가나 복구가 필요해질 때 슬롯 재사용과 `Generation`을 검토한다. 초기 설계안에 있던 슬롯 재사용은 이 범위에서 보류했다.

### 이동할 때만 Tick을 켜고 전체 슬롯 순회를 유지

- 직접 순회는 `Particles`를 저장 순서대로 읽는다. `InstanceToParticle`을 통한 순회는 비활성 슬롯을 피하지만 개체 ID를 한 번 더 조회한다. 이동 ID 목록은 움직이는 수가 적을 때 유리하고, 목표 재배정·도착·피격마다 목록을 맞춰야 한다.
- 형태 전환처럼 생존 구체 대부분이 움직이는 데모를 먼저 확인하려고 전체 순회를 유지했다. 목표가 배정되면 Tick을 켜고 이동할 개체가 없어지면 끈다. 여러 인스턴스를 갱신한 프레임에는 렌더 상태 갱신을 한 번 요청한다.
- 속도를 높이면 같은 경로를 더 적은 프레임에 이동할 수 있다. 이동 중인 개체 수가 같은 프레임의 비용과, 전환이 끝날 때까지 누적되는 작업량은 따로 측정해야 한다.

### 단일 도형 재구성은 최근접보다 순차 배정부터 확인

- 개체마다 가장 가까운 미할당 목표를 탐색하는 안을 검토했다. 근처 목표를 고르는 데 도움이 되지만, 구체가 1,000개라면 단순 탐색으로 약 50만 회의 거리 비교가 필요하며 처리 순서에 따라 결과가 달라진다.
- 단일 도형에서는 활성 개체 ID 순서와 목표 배열 순서를 그대로 짝지어 먼저 시연하기로 했다. 목표 배열을 복사하거나 배정한 후보를 삭제할 필요가 없다. 인접 도형 사이 전달은 연결부 근처에서 출발 개체와 도착 목표를 고르는 별도 문제로 둔다. 순차 배정에서 경로 교차나 장거리 이동이 눈에 띄는지 Play로 확인한 뒤 최근접 배정의 가치도 비교할 수 있다.

### 피격 디버그 표시를 중앙 조준선으로 변경

- 인스턴스 번호만 로그에 쓰면 맞힌 구체를 확인하기 어려워, 번호로 다시 조회한 위치에 테두리를 그려 식별을 검증했다. 클릭 시 화살표를 표시하는 안도 시도했지만, 화면에서 잘 보이게 옮긴 화살표 시작점 때문에 실제 검사 방향과 어긋나 보였다. 시연에서는 화면 중앙의 십자 조준선으로 조준 위치를 보여주기로 했다.

## 확인한 동작과 초기 측정

| 확인 방법 | 확인한 내용 |
|---|---|
| 초기 샘플러 자동 테스트 | 구·박스, Seed 3개, 개체 수 3종의 18개 조합에서 목표 수·최소 간격·경계 검사 통과. 17개 조합은 확장 없이 생성됐고 1개 조합은 5% 선형 확장 후 생성됐다. |
| 초기 생성 시간 표본 | 300개 생성 약 5.2~5.5ms. 전수 거리 검사를 포함한 당시 실행 표본이다. 최종 실행 경로나 다른 방법과의 비교 수치는 아직 없다. [1단계 검증 기록](Stage1README.md#검증-기록--2026-11-09) |
| 에디터 Play 확인 | Actor의 이동·회전에 구체가 함께 움직였다. 중앙 조준선으로 반복 제거가 동작했고, `T`로 활성 구체를 로컬 +X 방향으로 1,000cm 이동시키면서 맞힌 구체도 제거할 수 있었다. |
| 미리보기 자동 테스트 | 중간 인스턴스 교환 삭제 뒤에도 생존 개체의 ID와 실제 위치가 유지되고, 양방향 대응이 일치했다. 번호가 바뀐 개체도 목표까지 이동했고, 도착 시 Tick이 꺼졌다. |
| 재구성 자동 테스트 | 50개 중 하나를 제거한 뒤 목표 49개가 생성됐다. 초기 생성 수는 유지됐으며, 비활성 슬롯을 건너뛰고 활성 개체 순으로 목표가 배정됐다. Play에서 재구성 전체 흐름을 실행하는 입력은 아직 연결 전이다. |

## 나중에 실측하거나 시연할 후보

| 비교 | 맞춰 둘 조건과 기록할 값 |
|---|---|
| 샘플링 조기 종료와 영역을 채운 뒤 부분 선택 | 같은 목표 수·간격·Seed에서 생성 시간, 도형의 빈 영역, 실루엣을 비교한다. |
| 배치 계수와 확장 정책 | 구·박스와 길쭉한 검 형태에서 개체 수와 Seed를 바꿔 최초 크기 성공률, 확장률·확장량, 최종 실루엣을 기록한다. |
| 생성 후 전수 검사 포함·제외 | 같은 입력에서 `ValidateTargets()` 포함 여부에 따른 생성 시간을 재고, 최소 간격·경계 검증은 자동 테스트에 유지한다. [전수 검사 정책](../SwarmBossDesign.md#생성-후-전수-검사의-사용-단계--2026-11-11-결정) |
| 기본 삭제와 교환 삭제 | ISM당 100개와 1,000개에서 앞·중간 슬롯 삭제를 비교한다. 엔진 인스턴스·충돌 갱신 시간과 게임 쪽 대응표 갱신 시간을 나눠 잰다. |
| 전체 슬롯, 생존 ID, 이동 ID 순회 | 초기 슬롯 수를 고정하고 생존 수와 이동 수를 따로 바꾼다. 예를 들어 1,000개 중 10개 이동과 100개 생존 중 100개 이동을 구분한다. 순회와 ISM 갱신을 따로 기록한다. |
